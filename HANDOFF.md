- **Subagent-Ergebnisse (auch Fork-Agents) nie ungeprüft übernehmen** — siehe Failed Approaches. Immer `git diff`/`git status` prüfen, wenn ein Agent behauptet, Code geändert zu haben, bevor man das für bare Münze nimmt.
- **`npm install`/`npm run` NIE im Haupt-Checkout ausführen** (Windows-DrvFs-Mount, geteilte `node_modules` — ein `npm install` würde Unix-Bin-Shims statt `.cmd`-Dateien erzeugen und `npm run` auf der Windows/Rider-Seite brechen). In einer eigenen, isolierten Worktree ist `npm install` dagegen unproblematisch (eigene `node_modules`-Kopie, bestätigt am players-Map-Branch). `node node_modules/typescript/bin/tsc -p tsconfig.json --noEmit` ist der Standard-Verifikationsschritt sonst.
- **Kein Firestore-Doppelschreiben** — der atomare Cutover ist umgesetzt; nicht nachträglich einen Parallel-Schreibpfad einbauen.
- **Commits bleiben lokal, NICHT pushen** (Standing-Rule, GitHub-Ruleset `NeverPushOnMain`) — User pusht selbst.
- **Mehrere Agenten können parallel an diesem Repo arbeiten** — vor jeder größeren Aufgabe `git worktree list` prüfen.
- **Ein gesetztes GitHub-Secret alleine bewirkt nichts** — es muss zusätzlich im `env:`-Block der jeweiligen Workflow-YAML referenziert werden (`${{ secrets.NAME }}`).
- **Nach einem großen Schema-Wechsel: Frontend-Deploy und Backend-Cron laufen unabhängig** — ein Frontend-Push kann live gehen, bevor der nächste Backend-Lauf das neue Datenschema geschrieben hat. Führte hier zu einem echten White-Screen-Vorfall (siehe Completed). Nach jedem größeren Schema-Wechsel: sofort einen Heavy-Lauf erzwingen (`gh workflow run dashboard-marktwerte.yml`), nicht auf den nächsten planmäßigen Cron warten.
- **GitHub Actions liest vom Remote `main`, nicht von lokalen Commits** — vor jeder Live-Verifikation eines frischen Fixes `git log origin/main --oneline` prüfen bzw. den User fragen, ob schon gepusht wurde.
- **Plan-Dokumente können durch spätere Korrekturen veraltet werden** — bei Arbeit an einem bereits laufenden Redesign immer den aktuellen Code, nicht den ursprünglichen Plantext, als Ground Truth nehmen.
- **Status-Code-Bedeutungen nicht neu raten** — `MDs/codes.md` hat die verifizierte Zuordnung inkl. Korrektur-Historie; nur bei neuem, bisher unbeobachtetem Code (aktuell nur Code 8 offen) überhaupt neu recherchieren, und dann nur mit echtem In-App-Beleg.
