# Grafische Tab-Indikatoren — Naming/Ablage-Kontrakt + Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Jeder der 9 App-Tabs (inkl. des neuen "Dashboard"-Tabs) bekommt ein eigenes Icon in Desktop-Nav +
Mobile-Burger-Menü, statt reinem Text-Label.

**Architecture:** Folgt 1:1 dem bestehenden Icon-Muster dieses Projekts (`frontend/public/icons-src/` als
Rohdatei-Staging, `frontend/src/components/icons.tsx` als finale, in React eingebettete `currentColor`-SVGs — exakt
wie bei den bereits vorhandenen Positions-/Status-Icons).

**Tech Stack:** Statische SVG-Dateien, React-Komponenten (kein neues Icon-Framework).

## Format-Invarianten der gelieferten SVGs (aus dem Claude-Web-Übergabedokument)

- `viewBox="0 0 24 24"`.
- `fill="currentColor"` **nur** am äußeren `<svg>`-Element — Kindelemente (`<path>` etc.) haben **kein** eigenes
  `fill`, sie erben es. Ein `fill` an einem Kindelement bricht die Farbsteuerung für dieses Element.
- Kein `stroke`, kein Hex-Farbwert, kein Gradient, kein `<style>`-Block.
- Icons haben bereits einen kalibrierten Innenrand (~3 Einheiten) — kein zusätzliches Padding beim Einbinden nötig.
- **Nur inline als JSX einbinden** (wie alle bestehenden Icons in `icons.tsx`) — **nicht** `<img src=...>` und
  **nicht** als CSS-`background-image`. Beides würde das SVG als eigenständiges Dokument laden, `currentColor` fällt
  dann auf Schwarz zurück und die Icons ignorieren Hell-/Dunkelmodus komplett.
- Beim Copy-Paste der Rohdatei-Attribute nach JSX: Bindestrich-Attribute werden camelCase (`fill-rule` →
  `fillRule`, `clip-rule` → `clipRule`) — relevant nur, falls beim Kopieren `fillRule` ergänzt werden muss (siehe
  Falle 1 unten), die aktuellen Dateien selbst brauchen das nicht.

## Farbklassen (Kontrast-geprüft, WCAG 1.4.11, Schwelle 3:1 gegen `slate-50` UND `slate-950` — App nutzt `darkMode:
"media"`, beide Modi müssen also funktionieren, nicht nur einer)

```
inaktiv:  text-slate-500                                  (braucht bewusst kein dark:-Pendant — 4,55:1 hell, 4,24:1 dunkel)
aktiv:    text-brand-600 dark:text-brand-400
hover:    hover:text-slate-600 dark:hover:text-slate-300
```

**Nicht verwenden** (geprüft, fallen durch): `brand-500`/`#0fc46a` (nur 2,20:1 gegen `slate-50`), `slate-600` als
Dark-Mode-Hover (2,66:1 gegen `slate-950`).

Diese Farbklassen gehören **auf das Icon selbst**, nicht nur implizit über `currentColor` vom Label geerbt — die
bestehende Nav-Button-Färbung (`isSelected`-Ternary in `App.tsx`, siehe Task 1 Step 4) setzt aktuell
`text-slate-900 dark:text-slate-50` fürs Label, wenn ausgewählt — das ist NICHT dieselbe Farbe wie oben fürs Icon
verlangt. Das Icon braucht deshalb eine **eigene** `className`, unabhängig von der Label-Textfarbe (siehe Step 4/5
für den genauen Code).

## Zielgröße

20px in der Desktop-Nav (`h-5 w-5`), 24px im Mobile-Menü (`h-6 w-6`, mehr Platz pro Zeile dort). Die Strichstärken
der gelieferten Icons sind auf 20px kalibriert (dünnste Form: die Linie in `tab-spekulation.svg`, 2,3 Einheiten ≈
1,9px bei 20px Darstellungsgröße) — nicht kleiner skalieren als 20px in der Desktop-Nav.

## Nicht-Ziele

- Keine Änderung an Tab-Reihenfolge, Tab-Labels oder Tab-Keys (Dashboard-Tab-Reihenfolge/-Label ist Teil des
  separaten Tages-Dashboard-Plans, nicht dieses hier).
- Keine Status-Badges/Benachrichtigungs-Indikatoren auf den Tabs (z.B. "neue Angebote seit letztem Besuch") — reine
  Identitäts-Icons pro Tab, wie im Chat geklärt.
- Kein Ersatz der bestehenden Text-Labels — Icon **zusätzlich** zum Label, nicht statt.
- Kein `<title>`-Element in den Icons (rein dekorativ, Tab-Label steht als Text daneben — ein `<title>` ließe
  Screenreader den Tab-Namen doppelt vorlesen).

- [ ] **Step 1: Jede der 9 Rohdateien lesen und Format-Check machen**

- [ ] **Step 2: 9 neue Icon-Komponenten in `icons.tsx` ergänzen**

Für jeden Tab eine Funktion nach folgendem Muster (Inhalt der `<path>`/sonstigen Kind-Elemente **1:1, unverändert**
aus der jeweiligen Rohdatei übernommen — siehe die zwei Fallen unten, BEVOR irgendein Pfad umstrukturiert wird):

```tsx
export function IconTabDashboard(props: SVGProps<SVGSVGElement>) {
  return (
    <svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 24 24" fill="currentColor" role="img" aria-label="Dashboard" {...props}>
      {/* Pfade 1:1 aus frontend/public/icons-src/tab-dashboard.svg uebernommen */}
    </svg>
  );
}
```

Analog für `IconTabTeam`, `IconTabSpekulation`, `IconTabWunschkader`, `IconTabTransfermarkt`, `IconTabLiga`,
`IconTabAlleSpieler`, `IconTabMlGenauigkeit`, `IconTabFeedback` — `aria-label` jeweils das deutsche Tab-Label aus der
Tabelle oben.

**Falle 1 — `tab-ml-genauigkeit.svg` (Tacho):** das Skalenband ist EIN `<path>` mit zwei gegenläufigen Bögen; der
Ausschnitt in der Mitte entsteht ausschließlich aus der Wicklungsrichtung (Nonzero-Fill-Regel). Diesen Pfad **nicht**
in zwei `<path>`-Elemente auftrennen — sonst wird das Band zur gefüllten Halbscheibe und die Nadel verschwindet
darin. Falls doch aufgetrennt werden muss: `fillRule="evenodd"` ergänzen, dann ist die Wicklungsrichtung egal.

**Falle 2 — `tab-spekulation.svg` (Kursverlauf):** die Linie besteht aus drei gefüllten Vierecken PLUS drei Kreisen
exakt auf den Knickpunkten (die Kreise ersetzen `stroke-linejoin: round`, da `stroke` nicht erlaubt ist). Alle sechs
Elemente gehören zusammen — keinen der Kreise weglassen, sonst entsteht eine sichtbare spitze Kerbe an einem Knick.

Bei beiden: einfach die komplette Rohdatei 1:1 in die neue Komponente kopieren, nichts "aufräumen" oder
vereinfachen.

- [ ] **Step 4: Desktop-`<nav>` verdrahten**

Im bestehenden `<nav>`-Rendering (`TABS.map(...)`, `isActive`/`isSelected` bereits vorhandene lokale Variablen), das
Icon vor dem Label ergänzen — mit **eigener** Farbklasse (siehe "Farbklassen" oben, unabhängig von der
Label-Textfarbe):

```tsx
{TABS.map((tab) => {
  const isActive = ACTIVE_TABS.has(tab.key);
  const isSelected = tab.key === activeTab;
  const Icon = TAB_ICON[tab.key];
  const iconTone = isSelected
    ? "text-brand-600 dark:text-brand-400"
    : "text-slate-500 hover:text-slate-600 dark:hover:text-slate-300";
  return (
    // bestehendes <button> unveraendert, Inhalt bekommt zusaetzlich:
    <>
      <Icon className={`h-5 w-5 ${iconTone}`} aria-hidden="true" />
      {tab.label}
    </>
  );
})}
```

(Exakte Einbettung an die bestehende JSX-Struktur der Nav-Buttons anpassen, z.B. mit `flex items-center gap-1.5` um
Icon+Label sauber nebeneinander zu setzen. `aria-hidden="true"` auf dem Icon, weil `aria-label` schon auf dem
sichtbaren Text-Label sitzt und sonst doppelt vorgelesen würde. Für inaktive/gesperrte Tabs (`!isActive`, zeigen
"(bald)") reicht die inaktive Tonalität ohne Hover-State — dort gilt einfach `text-slate-500` ohne Hover-Variante,
kein eigener drittter Zustand nötig, wie im "Farbklassen"-Abschnitt festgelegt.)
